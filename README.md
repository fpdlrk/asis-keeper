# ASIS 원본 보관함

변경 전(ASIS) 원본을 화면별로 잠가 보관하고, 변경 후(TOBE)와 비교해 고객 전달용 보고서를 만드는 오프라인 도구입니다.

## 실행
`index.html`을 Chrome 또는 Edge로 엽니다(더블클릭). 서버나 설치가 필요 없고, 폴더 전체(`css/`, `js/` 포함)를 함께 옮기면 됩니다.

## 상태 모델
- `app` — 앱 전체 상태 (`js/state.js`)
  - `app.project` 열린 프로젝트, `app.root` 그 루트 폴더 핸들, `app.tab` 보고 있는 탭, `app.statusFilter` 상태 필터, `app.statusCounts` 상태별 화면 수
  - `app.screen` 열려 있는 화면. 현황일 때는 `null`. 구조는 `createScreenState()`(`js/screen.js`) 참고
- 편집기 id 규칙: 글 입력란은 `TEXT_FIELD_FILES`의 키(`memo` 등), SQL 블록은 접두어 + 블록 id
  - `a:` 기존 SQL, `t:` 신규 SQL, `p:` 신규 탭 왼쪽의 기존 SQL(읽기 전용), `r:` 예전 롤백 SQL
  - 직접 문자열을 만들지 말고 `editorId('tobe', blockId)`를 씁니다.
- 변경 감지: 처음 그릴 때와 등록할 때 값을 `app.screen.savedValues`에 기억하고, 지금 값과 비교합니다(`isDirty`).

## 기존(ASIS) 잠금과 잠금 풀기
- 등록하면 `meta.asisLocked = true` 가 되고 기존 SQL·파일은 읽기 전용이 됩니다. 이때 파일별 SHA-256을 `meta.hashes`에 남겨 원본 무결성을 확인합니다.
- 잘못 등록한 내용을 바로잡아야 할 때는 잠긴 안내 띠 오른쪽의 **[잠금 풀기]** 로 풉니다. **사유 입력이 필수**이며, 사유는 `meta.asisUnlockLog`에 쌓입니다(`{at, by, reason, relockedAt}`). 지우는 기능은 없습니다.
- 풀린 동안에는 기존 SQL·파일을 다시 고칠 수 있고, **[수정 내용 등록 후 다시 잠그기]** 로 잠그면 `meta.hashes`를 지금 내용으로 다시 계산합니다. 마지막 해제 이력에 `relockedAt`이 채워집니다.
- `meta.asisSavedAt`(최초 등록 시각)은 다시 잠가도 바뀌지 않습니다. 해제·재잠금 시점은 해제 이력에서 봅니다.
- 해제 이력이 있으면 기존 SQL 탭에 **잠금 해제 이력 띠**가 하나 더 나오고, 현황 '점검 필요'와 보고서의 '원본 무결성'에도 해제 사실이 표시됩니다(보고서에는 횟수만, 사유 전문은 앱에만).

## 코드 규칙

> ### 0. 가장 중요한 규칙 — 사람이 읽고 고칠 수 있어야 합니다
>
> 이 도구는 **빌드 도구도, 프레임워크도, 테스트도 없습니다.** 브라우저가 읽는 코드가 곧 원본이고,
> 고치는 사람은 `index.html`과 `js/*.js`를 **그대로 열어서** 읽습니다.
> 그래서 "돌아가는 코드"보다 **"다음 사람이 읽고 고칠 수 있는 코드"가 우선입니다.**
>
> - **압축·난독화·자동 생성 코드를 두지 않습니다.** (예외: `js/vendor/*.js` — 외부 라이브러리(Ace)이며 직접 수정하지 않습니다)
> - **영리한 한 줄보다 평범한 여러 줄.** 읽는 사람이 멈칫하면 그 코드는 틀린 코드입니다.
> - **한 함수는 한 가지 일만.** 길어지면 이름 붙여 쪼갭니다.
> - **이름이 주석을 대신하게** 쓰고, 그래도 설명이 필요한 "왜"는 주석으로 남깁니다.
> - **숨은 규칙을 만들지 않습니다.** 값의 의미가 눈에 보이지 않으면 상수로 꺼내 이름과 주석을 답니다
>   (예: `NO_ASIS_PAIR`, `FILE_STRUCTURE_VERSION`).
> - **기존 코드의 모양을 따릅니다.** 들여쓰기·주석 밀도·이름 짓는 방식을 새로 만들지 않습니다.
> - 아래 1~7번 규칙은 모두 이 원칙을 지키기 위한 구체적인 방법입니다.

1. **스크립트 구조**: `file://`에서는 ES 모듈(`import`)을 쓸 수 없어 일반 `<script>`를 `index.html`에 적힌 순서대로 읽습니다.
   - 각 파일 최상위의 `const`/`let`/`function`은 모든 파일이 공유합니다. **이름이 겹치면 안 되고**, `window` 기본 속성 이름(`screen`, `status`, `name`, `history`, `closed` 등)도 피합니다.
   - 파일을 읽는 순간 실행되는 코드는 두지 않습니다. 이벤트 연결은 각 파일의 `init*()` 안에서 하고, `main.js`가 순서대로 부릅니다.
   - 새 파일은 `index.html`의 스크립트 목록에서 그 파일이 쓰는 파일보다 뒤, `main.js`보다 앞에 넣습니다.
2. **이름**: 무엇인지 알 수 있는 이름을 씁니다. 한 글자 변수나 줄임말(예: `ed`, `kv`, `m`)은 쓰지 않습니다.
3. **주석**: 파일 머리에 역할을, 함수마다 하는 일·인자·반환값을 적습니다. 왜 그렇게 했는지가 필요하면 이유도 남깁니다.
4. **공통 함수**: 두 번 이상 쓰는 로직은 공통 함수로 만듭니다. 새로 만들기 전에 `utils.js`, `fs.js`, `screen-data.js`, `dialog.js`에 이미 있는지 먼저 봅니다.
5. **브라우저 기본 창 금지**: `alert`/`confirm`/`prompt` 대신 `askText`/`askConfirm`/`toast`를 씁니다.
6. **오래 걸리는 작업**: 파일을 읽고 쓰는 작업은 `withBusy('…하는 중…', async () => { … })`로 감싸 다른 조작을 막습니다. 확인 창은 `withBusy` 바깥에서 띄웁니다.
7. **HTML에 넣는 글자**: 사용자가 입력한 값은 반드시 `escapeHtml()`을 거칩니다.

## 기존 SQL 과 신규 SQL 의 짝 (asisId)
신규 SQL 블록마다 **"어느 기존 SQL을 바꾼 것인지"** 를 직접 지정합니다. 순서로 짝짓지 않습니다.

- 저장: `meta.sqlBlocks.tobe[].asisId`
  - `'<기존 블록 id>'` → 그 블록과 비교
  - `''`(`NO_ASIS_PAIR`) → 짝 없음 = **신규 쿼리**. 나란히 보기의 왼쪽 칸이 숨겨지고 신규 SQL 만 넓게 보입니다
  - **값이 없으면** 예전 데이터 → 같은 순서의 기존 블록 (선택 상자에 `자동(순서)`로 표시되고, 다음 등록 때 실제 값으로 굳습니다)
- 고르는 곳: 신규 SQL **블록 머리**의 `기존` 선택 상자. 새 블록은 `없음 (신규 쿼리)`에서 시작합니다.
  (왼쪽 칸은 `없음`일 때 숨겨지므로 선택 상자를 그 안에 두면 안 됩니다 — 다시 고를 수 없게 됩니다)
- 짝을 찾는 함수는 `findPairedAsisBlock()`(`screen-data.js`) 하나뿐이고, **나란히 보기·비교 탭·비교 창·보고서·기존 SQL 가져오기가 모두 이 함수를 씁니다.**
- 그 덕분에 블록 순서를 바꾸거나 중간에 신규 쿼리를 끼워 넣어도 비교가 어긋나지 않고,
  비교 탭·보고서가 `변경` / `신규 쿼리` / `신규에 없음` 세 가지를 구분합니다.

## 프로젝트 (루트 폴더 여러 개)
상단 왼쪽 단추로 등록한 프로젝트를 전환합니다. 프로젝트 하나 = 루트 폴더 하나입니다.

- 저장 위치(IndexedDB): `projects` = `[{id, name, handle, lastOpenedAt}]`, `lastProjectId` = 마지막으로 연 프로젝트
- `id` 는 폴더 이름과 무관한 고유 값입니다. 접어 둔 폴더(`closed:<id>`)와 탐색기 경로(`rootPath:<id>`)를 **id 기준**으로 저장해, 이름이 같은 다른 폴더끼리 설정이 섞이지 않습니다.
- `name` 은 목록·상단·보고서에 쓰이는 이름이며 폴더 이름과 달라도 됩니다(`rootLabel()`). 바꿔도 폴더 이름은 그대로입니다.
- **폴더 권한은 세션이 끊기면 풀립니다.** 핸들은 남지만 `requestPermission()` 은 클릭 안에서만 띄울 수 있어, 시작할 때는 권한이 살아 있을 때만 자동으로 엽니다. 끊겼으면 단추에 열쇠 표시를 띄우고, 목록에서 고르는 순간 허용을 요청합니다. 이때 `app.project` 는 있고 `app.root` 는 `null` 입니다.
- 예전 버전의 단일 루트 설정(`root` 키)은 처음 실행할 때 목록의 첫 프로젝트로 자동 이전됩니다(`migrateLegacyProject`).
- `목록에서 제거`는 목록과 그 프로젝트 설정만 지우고 폴더·파일은 건드리지 않습니다.
- **폴더가 지워진 경우**: 브라우저가 기억한 핸들은 폴더를 지워도 남으므로, 열 때와 창으로 돌아올 때(포커스) 실제로 있는지 확인합니다(`folderExists`).
  프로젝트 폴더가 없으면 '폴더가 없습니다'를 알리고 목록·설정에서 제거합니다(`dropMissingProject`). 메뉴·폴더가 없어졌으면 트리를 새로 그리고, 열어 둔 화면이면 닫습니다(`recheckFolders`).
  '없음'(`NotFoundError`)일 때만 제거하며, 권한 같은 다른 오류로는 지우지 않습니다.

## 메뉴(화면)와 폴더(묶음)
루트 아래 폴더는 `meta.json` 이 있는지로 둘로 나뉩니다. 둘 다 우클릭 메뉴로 만듭니다.

| | 메뉴 = 화면(페이지) | 폴더 = 메뉴 묶음 |
|---|---|---|
| 만들기 | `하위 메뉴 추가` | `하위 폴더 추가` |
| `meta.json` | 있음 | **없음** |
| 눌렀을 때 | 본문에 화면이 열림 | 열고 닫기만 (본문 UI 없음) |
| 트리 표시 | 이름 + 상태 점 | 폴더 아이콘 + 이름 + 하위 화면 수 |
| 집계 | 상태·운영 반영률·보고서에 포함 | 집계에서 빠짐 |
| 하위에 넣기 | **불가** (파일처럼 끝 노드) | 메뉴·폴더 모두 가능 |

VS Code 의 파일/폴더와 같은 규칙입니다. 화면은 그 자체가 내용을 담는 페이지이므로 하위를 가질 수 없어, 우클릭 메뉴에 ‘하위 … 추가’가 나오지 않고 이동·복사의 위치 목록에도 나오지 않습니다.
이름 변경·이동·복사·탐색기 경로 복사는 둘 다 같게 동작합니다. 루트 우클릭 메뉴(‘루트 경로 다시 설정’ 포함)는 좌측 사이드바의 빈 공간을 우클릭해 엽니다.

## 데이터 폴더 구조 (루트 아래 화면 폴더마다)
```
meta.json                 상태·티켓·작업자·원본 위치·상태 이력·SQL 블록 목록(asisId 포함)·ASIS 해시·잠금 해제 이력·SQL 마다 쌓는 이력(sqlBlocks[].log)
memo.md                   비고/메모
asis/sql/*.sql            기존 SQL (등록하면 잠김)
asis/files/<원본 경로>    기존 파일 (등록하면 잠김) — 예전 데이터만. 지금은 화면에서 올리지 않음
tobe/sql/*.sql            신규 SQL
tobe/files/<원본 경로>    신규 파일 — 예전 데이터만. 지금은 화면에서 올리지 않음
tobe/history/*            신규 SQL 이전 버전
service/ object/ code/    정의서 — <탭>/items.json (항목 · 표 · 이력). 예전 *.md · overview.json 은 남겨 둠(처음 열 때 옮겨 보여 줌)
attach/                   참고 파일
```
루트에는 `.reports/`(보고서), `.migration/`(구조 변환 기록)이 생깁니다.

## SQL 탭과 SQL 마다 쌓는 이력
기존 SQL 탭·신규 SQL 탭 안에서 **SQL 하나 = 탭 하나**로 보여 줍니다(`js/screen-sqltabs.js`).

- 고른 탭의 블록만 보이고 나머지는 숨깁니다. **블록은 모두 화면에 그대로 있으므로** 등록·비교 탭·보고서·짝 찾기는 예전처럼 화면 순서(`readBlockInputs`)대로 읽습니다.
- 탭이 많으면 탭 줄을 좌우로 스크롤합니다(마우스 휠도 가로로 움직임). 오른쪽 **[▾ 전체 n]** 에서 목록으로 골라 이동합니다.
- 탭의 **×** 로 삭제합니다(확인 창). 잠긴 기존 SQL 은 × 와 [+ SQL 추가]가 없습니다. 등록하지 않은 변경이 있는 탭에는 ● 가 붙습니다.
- **[+ SQL 추가]** 창: 이름·SQL(필수), 비교할 기존 SQL(신규만, 처음은 '없음'), 이력(선택). 창은 처음 추가할 때만 쓰고, 이름·SQL 수정은 탭 본문에서 합니다.
  추가한 SQL 은 다른 입력처럼 저장 바 [등록](기존 SQL 은 '등록 후 잠그기')을 눌러야 저장됩니다.
- SQL 이 하나도 없으면 빈 블록을 만들지 않고 안내만 보여 줍니다.

**이력**은 탭 본문 아래에서 SQL 마다 따로 쌓입니다.
- 저장: `meta.sqlBlocks.{asis|tobe}[].log = [{at, by, text}]` — `at` 남긴 시각, `by` 화면 위 작업자. 목록은 최근 것이 위.
- 이미 등록된 SQL 은 [이력 저장](또는 Ctrl+Enter) 즉시 `meta.json`에 저장됩니다(잠긴 기존 SQL 도 이력은 남길 수 있음).
  아직 등록 전인 SQL 은 화면에만 남았다가 그 SQL 을 등록할 때 함께 저장됩니다.
- 고치거나 지우는 기능은 없습니다. SQL 을 삭제하면 그 이력도 함께 지워집니다. `log` 가 없으면 이력이 없는 SQL 입니다.

## 표(그리드) 기능 — `js/screen-grid.js`
서비스 · 오브젝트 · 코드분류의 모든 표에 적용됩니다. 칸마다 `<input>`이 있는 표 위에 아래 기능을 얹었습니다(외부 라이브러리 없음).

- **셀 범위 선택**: 드래그 · Shift+클릭 · Shift+방향키 → 파란색 표시. 한 칸 안에서 끌면 평소처럼 글자 선택, 다른 칸으로 넘어가면 범위 선택
- **Ctrl+C / Ctrl+X**: 범위를 '칸은 탭, 줄은 줄바꿈' 글로 복사(엑셀과 같은 형식 — 엑셀이나 이 표에 그대로 붙여짐) · **Delete / Backspace**: 범위 비우기 · **Esc**: 범위 풀기
- **키보드**: 방향키 칸 이동, Enter / Shift+Enter 아래 / 위(마지막 줄에서 Enter 면 줄 추가), Tab / Shift+Tab 옆 칸(줄 끝이면 다음 줄)
  - ←→ 는 글자 맨 앞/끝이거나 칸 전체가 선택됐을 때만 옆 칸으로. 방향키로 들어간 칸은 글자 전체가 선택되어 바로 치면 바뀜(엑셀과 같음)
  - 한글 조합 중에는 키를 가로채지 않습니다.
- **붙여넣기**: 여러 칸·여러 줄을 붙여넣은 칸부터 오른쪽·아래로 채움(덮어쓰기). 칸은 탭, 탭이 없으면 공백 2칸 이상으로 나눔(`splitTableText`).
  줄이 모자라면 행 추가, 칸이 넘치면 버리고 알림. 붙여넣은 범위는 선택된 채로 보여 줌
- **되돌리기(Ctrl+Z) · 다시 실행(Ctrl+Y, Ctrl+Shift+Z)**: 붙여넣기 · 범위 지우기 · 잘라내기. 표마다 `app.screen.gridPasteHistory[표 id] = {undo, redo}`(최대 20번).
  그 표에 직접 입력하거나 행을 추가·삭제하면 기록을 지움 — 그 뒤 Ctrl+Z/Y 는 브라우저 기본(입력한 글자)
- **날짜 칸**(`GRID_COLUMNS`의 `types`가 `'date'`): 글 입력칸에 `20260101`처럼 쳐도 칸을 떠날 때 `2026-01-01`로 맞춤.
  `2026.1.1` · `2026. 01. 01` · `2026/01/01`도 됨. 없는 날짜(2026-02-30 등)나 날짜가 아닌 값은 그대로 두고 빨갛게 표시(`.invalid`)
  (브라우저 날짜 입력칸은 방향키·범위 선택·복사와 함께 쓰기 어려워 쓰지 않음)
- **모양·색**: 엑셀처럼 칸 안의 입력칸은 테두리·배경 없이 투명(칸과 한 몸), 입력 중인 칸은 칸 전체가 연한 파란색. 색은 `css/app.css` 맨 위 토큰에서 바꿉니다 —
  `--grid-focus-bg`(입력 중인 칸) · `--grid-focus-line`(그 칸의 안쪽 선) · `--grid-sel-bg`(범위로 선택한 칸)

## 정의서 탭 (서비스 · 오브젝트 · 코드분류)
SQL 탭과 같은 모양입니다(`js/screen-defs.js`, 탭 줄·이력은 `screen-sqltabs.js`의 공통 함수).

- **항목 하나 = 탭 하나**(예: 서비스 하나). [+ 서비스 추가] 창에서 이름(필수)·이력(선택)을 받아 만들고, 표는 탭 본문에서 채웁니다.
- 항목 본문: 이름 + 표 여러 개 + 이력. 표 구성은 `DEF_TABS[탭].grids`, 열은 `GRID_COLUMNS['<탭>.<표 키>']`(`constants.js`)
  - 서비스: 개요 · 속성정의 · 기능정의 / 오브젝트: 개요 · 속성 · 하위 오브젝트 / 코드분류: 개요 · 공통코드내역관리 · 시스템코드관리
  - **개요 두 개(오브젝트·코드분류)를 뺀 열 이름은 임시안**입니다. 확정되면 `GRID_COLUMNS`만 고치면 됩니다(값은 열 순서대로 저장되므로 순서를 바꿀 땐 기존 데이터 확인).
- 탭 × 삭제, [▾ 전체], 변경 표시 ●, 표 붙여넣기·Ctrl+Z/Y 모두 SQL 탭·표와 같습니다.
- 저장: 저장 바 [등록] → `<탭>/items.json = [{id, title, grids: {표 키: [[칸…]…]}, log?}]`. 항목을 다 지워도 빈 목록을 저장합니다.
- 이력: 등록된 항목은 [이력 저장] 즉시 `items.json`에 저장, 등록 전 항목은 등록할 때 함께 저장(SQL 이력과 같은 규칙). 보고서에는 넣지 않습니다.
- **예전 데이터**: `items.json`이 없으면 예전 글 입력란(`service/overview.md` 등)과 개요 표(`object/overview.json`, `code/overview.json`)를
  '기본' 항목 하나로 옮겨 보여 줍니다(`loadDefItems`). 글은 붙여넣기 규칙(탭 / 공백 2칸 이상)으로 나누고, 칸이 넘치면 마지막 칸에 이어 붙입니다.
  예전 내용도 등록했던 것으로 보고(● 없음), 다음 [등록] 때 `items.json`으로 저장됩니다. 예전 파일은 지우지 않습니다.
- 표는 같은 종류가 화면에 여러 개 있으므로 표마다 고유 id(`grid-<탭>-<항목 id>-<표 키>`)를 주고, 열 구성은 표의 `data-cols`로 찾습니다.
