# ASIS 원본 보관함

변경 전(ASIS) 원본을 화면별로 잠가 보관하고, 변경 후(TOBE)와 비교해 고객 전달용 보고서를 만드는 오프라인 도구입니다.

## 실행
`index.html`을 Chrome 또는 Edge로 엽니다(더블클릭). 서버나 설치가 필요 없고, 폴더 전체(`css/`, `js/` 포함)를 함께 옮기면 됩니다.

## 상태 모델
- `app` — 앱 전체 상태 (`js/state.js`)
  - `app.project` 열린 프로젝트, `app.root` 그 루트 폴더 핸들, `app.tab` 보고 있는 탭, `app.statusFilter` 상태 필터, `app.statusCounts` 상태별 화면 수
  - `app.screen` 열려 있는 화면. 현황일 때는 `null`. 구조는 `createScreenState()`(`js/screen.js`) 참고
- 편집기 id 규칙: 글 입력란은 `TEXT_FIELD_FILES`의 키(`memo` 등), SQL 블록은 접두어 + 블록 id
  - `a:` 기존 SQL, `t:` 신규 SQL, `p:` 신규 탭 왼쪽의 기존 SQL(읽기 전용), `r:` 예전 롤백 SQL
  - 직접 문자열을 만들지 말고 `editorId('tobe', blockId)`를 씁니다.
- 변경 감지: 처음 그릴 때와 등록할 때 값을 `app.screen.savedValues`에 기억하고, 지금 값과 비교합니다(`isDirty`).

## 기존(ASIS) 잠금과 잠금 풀기
- 등록하면 `meta.asisLocked = true` 가 되고 기존 SQL·파일은 읽기 전용이 됩니다. 이때 파일별 SHA-256을 `meta.hashes`에 남겨 원본 무결성을 확인합니다.
- 잘못 등록한 내용을 바로잡아야 할 때는 잠긴 안내 띠 오른쪽의 **[잠금 풀기]** 로 풉니다. **사유 입력이 필수**이며, 사유는 `meta.asisUnlockLog`에 쌓입니다(`{at, by, reason, relockedAt}`). 지우는 기능은 없습니다.
- 풀린 동안에는 기존 SQL·파일을 다시 고칠 수 있고, **[수정 내용 등록 후 다시 잠그기]** 로 잠그면 `meta.hashes`를 지금 내용으로 다시 계산합니다. 마지막 해제 이력에 `relockedAt`이 채워집니다.
- `meta.asisSavedAt`(최초 등록 시각)은 다시 잠가도 바뀌지 않습니다. 해제·재잠금 시점은 해제 이력에서 봅니다.
- 해제 이력이 있으면 기존 SQL 탭에 **잠금 해제 이력 띠**가 하나 더 나오고, 현황 '점검 필요'와 보고서의 '원본 무결성'에도 해제 사실이 표시됩니다(보고서에는 횟수만, 사유 전문은 앱에만).

## 코드 규칙

> ### 0. 가장 중요한 규칙 — 사람이 읽고 고칠 수 있어야 합니다
>
> 이 도구는 **빌드 도구도, 프레임워크도, 테스트도 없습니다.** 브라우저가 읽는 코드가 곧 원본이고,
> 고치는 사람은 `index.html`과 `js/*.js`를 **그대로 열어서** 읽습니다.
> 그래서 "돌아가는 코드"보다 **"다음 사람이 읽고 고칠 수 있는 코드"가 우선입니다.**
>
> - **압축·난독화·자동 생성 코드를 두지 않습니다.** (예외: `js/vendor/ace-bundle.js` — 외부 라이브러리이며 직접 수정하지 않습니다)
> - **영리한 한 줄보다 평범한 여러 줄.** 읽는 사람이 멈칫하면 그 코드는 틀린 코드입니다.
> - **한 함수는 한 가지 일만.** 길어지면 이름 붙여 쪼갭니다.
> - **이름이 주석을 대신하게** 쓰고, 그래도 설명이 필요한 "왜"는 주석으로 남깁니다.
> - **숨은 규칙을 만들지 않습니다.** 값의 의미가 눈에 보이지 않으면 상수로 꺼내 이름과 주석을 답니다
>   (예: `NO_ASIS_PAIR`, `FILE_STRUCTURE_VERSION`).
> - **기존 코드의 모양을 따릅니다.** 들여쓰기·주석 밀도·이름 짓는 방식을 새로 만들지 않습니다.
> - 아래 1~7번 규칙은 모두 이 원칙을 지키기 위한 구체적인 방법입니다.

1. **스크립트 구조**: `file://`에서는 ES 모듈(`import`)을 쓸 수 없어 일반 `<script>`를 `index.html`에 적힌 순서대로 읽습니다.
   - 각 파일 최상위의 `const`/`let`/`function`은 모든 파일이 공유합니다. **이름이 겹치면 안 되고**, `window` 기본 속성 이름(`screen`, `status`, `name`, `history`, `closed` 등)도 피합니다.
   - 파일을 읽는 순간 실행되는 코드는 두지 않습니다. 이벤트 연결은 각 파일의 `init*()` 안에서 하고, `main.js`가 순서대로 부릅니다.
   - 새 파일은 `index.html`의 스크립트 목록에서 그 파일이 쓰는 파일보다 뒤, `main.js`보다 앞에 넣습니다.
2. **이름**: 무엇인지 알 수 있는 이름을 씁니다. 한 글자 변수나 줄임말(예: `ed`, `kv`, `m`)은 쓰지 않습니다.
3. **주석**: 파일 머리에 역할을, 함수마다 하는 일·인자·반환값을 적습니다. 왜 그렇게 했는지가 필요하면 이유도 남깁니다.
4. **공통 함수**: 두 번 이상 쓰는 로직은 공통 함수로 만듭니다. 새로 만들기 전에 `utils.js`, `fs.js`, `screen-data.js`, `dialog.js`에 이미 있는지 먼저 봅니다.
5. **브라우저 기본 창 금지**: `alert`/`confirm`/`prompt` 대신 `askText`/`askConfirm`/`toast`를 씁니다.
6. **오래 걸리는 작업**: 파일을 읽고 쓰는 작업은 `withBusy('…하는 중…', async () => { … })`로 감싸 다른 조작을 막습니다. 확인 창은 `withBusy` 바깥에서 띄웁니다.
7. **HTML에 넣는 글자**: 사용자가 입력한 값은 반드시 `escapeHtml()`을 거칩니다.

## 기존 SQL 과 신규 SQL 의 짝 (asisId)
신규 SQL 블록마다 **"어느 기존 SQL을 바꾼 것인지"** 를 직접 지정합니다. 순서로 짝짓지 않습니다.

- 저장: `meta.sqlBlocks.tobe[].asisId`
  - `'<기존 블록 id>'` → 그 블록과 비교
  - `''`(`NO_ASIS_PAIR`) → 짝 없음 = **신규 쿼리**. 나란히 보기의 왼쪽 칸이 숨겨지고 신규 SQL 만 넓게 보입니다
  - **값이 없으면** 예전 데이터 → 같은 순서의 기존 블록 (선택 상자에 `자동(순서)`로 표시되고, 다음 등록 때 실제 값으로 굳습니다)
- 고르는 곳: 신규 SQL 블록 왼쪽 칸 머리의 선택 상자. 새 블록은 `없음 (신규 쿼리)`에서 시작합니다.
- 짝을 찾는 함수는 `findPairedAsisBlock()`(`screen-data.js`) 하나뿐이고, **나란히 보기·비교 탭·비교 창·보고서·기존 SQL 가져오기가 모두 이 함수를 씁니다.**
- 그 덕분에 블록 순서를 바꾸거나 중간에 신규 쿼리를 끼워 넣어도 비교가 어긋나지 않고,
  비교 탭·보고서가 `변경` / `신규 쿼리` / `신규에 없음` 세 가지를 구분합니다.

## 프로젝트 (루트 폴더 여러 개)
상단 왼쪽 단추로 등록한 프로젝트를 전환합니다. 프로젝트 하나 = 루트 폴더 하나입니다.

- 저장 위치(IndexedDB): `projects` = `[{id, name, handle, lastOpenedAt}]`, `lastProjectId` = 마지막으로 연 프로젝트
- `id` 는 폴더 이름과 무관한 고유 값입니다. 접어 둔 폴더(`closed:<id>`)와 탐색기 경로(`rootPath:<id>`)를 **id 기준**으로 저장해, 이름이 같은 다른 폴더끼리 설정이 섞이지 않습니다.
- `name` 은 목록·상단·보고서에 쓰이는 이름이며 폴더 이름과 달라도 됩니다(`rootLabel()`). 바꿔도 폴더 이름은 그대로입니다.
- **폴더 권한은 세션이 끊기면 풀립니다.** 핸들은 남지만 `requestPermission()` 은 클릭 안에서만 띄울 수 있어, 시작할 때는 권한이 살아 있을 때만 자동으로 엽니다. 끊겼으면 단추에 열쇠 표시를 띄우고, 목록에서 고르는 순간 허용을 요청합니다. 이때 `app.project` 는 있고 `app.root` 는 `null` 입니다.
- 예전 버전의 단일 루트 설정(`root` 키)은 처음 실행할 때 목록의 첫 프로젝트로 자동 이전됩니다(`migrateLegacyProject`).
- `목록에서 제거`는 목록과 그 프로젝트 설정만 지우고 폴더·파일은 건드리지 않습니다.

## 메뉴(화면)와 폴더(묶음)
루트 아래 폴더는 `meta.json` 이 있는지로 둘로 나뉩니다. 둘 다 우클릭 메뉴로 만듭니다.

| | 메뉴 = 화면(페이지) | 폴더 = 메뉴 묶음 |
|---|---|---|
| 만들기 | `하위 메뉴 추가` | `하위 폴더 추가` |
| `meta.json` | 있음 | **없음** |
| 눌렀을 때 | 본문에 화면이 열림 | 열고 닫기만 (본문 UI 없음) |
| 트리 표시 | 이름 + 상태 점 | 폴더 아이콘 + 이름 + 하위 화면 수 |
| 집계 | 상태·운영 반영률·보고서에 포함 | 집계에서 빠짐 |
| 하위에 넣기 | **불가** (파일처럼 끝 노드) | 메뉴·폴더 모두 가능 |

VS Code 의 파일/폴더와 같은 규칙입니다. 화면은 그 자체가 내용을 담는 페이지이므로 하위를 가질 수 없어, 우클릭 메뉴에 ‘하위 … 추가’가 나오지 않고 이동·복사의 위치 목록에도 나오지 않습니다.
이름 변경·이동·복사·탐색기 경로 복사는 둘 다 같게 동작합니다. 루트 우클릭 메뉴(‘루트 경로 다시 설정’ 포함)는 좌측 사이드바의 빈 공간을 우클릭해 엽니다.

```

asis/sql/*.sql            기존 SQL (등록하면 잠김)

tobe/sql/*.sql            신규 SQL
tobe/files/<원본 경로>    신규 파일
tobe/history/*            신규 SQL 이전 버전
```
